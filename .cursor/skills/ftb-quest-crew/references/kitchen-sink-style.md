# Kitchen-sink quest style bar (structure / design / voice)

Target: tutorial chapters with the pacing and structural polish of top kitchen-sink quest books — **original text only**.

## Structure

- One major mod ≈ one chapter (advanced sibling chapter only when systems are huge: e.g. base tech vs reactors)  
- Chapter groups: Main, Tech, Magic, Power, Storage, Logistics, Resources, Exploration, Tools and Gear  
- Progressive spine with side branches  
- Quests are lessons; checkmarks for pure reading/onboarding  

## Design / layout

- Stages flow left→right or top→bottom in readable columns  
- Early hub quest larger (`octagon` / bigger `size`)  
- Related machines clustered  
- Dependency lines tell a story; avoid spaghetti merges  
- Hide pure license/meta quests if needed; never clutter the learner path  

## Text style

- Title + subtitle + multipage description  
- Heavy but purposeful color markup on machine/resource names  
- Explain GUI colors, cable modes, dump buttons, hollow multiblocks, channel rules  
- Pagebreaks for long multiblock/process guides  
- Friendly expert voice, second person, concrete steps  
- Pack-neutral wording (no third-party pack names)

## Rewards style

- Small XP almost always  
- Item rewards are **components that help the next steps in the same mod**  
- Chapter-local reward tables by tier (basic mats / mid components / rarer goodies)  
- Random/loot tables weighted; early tables common and useful  
- Do not reward skips that erase the lesson  
- Do not dump endgame items in early quests  

## Depth expectations

Deep tech/magic chapters are large (dozens of quests) when the mod deserves it.  
Shallow QoL mods should not get giant chapters — prefer a short tip chapter or skip.

## Generation rule

Match this **structure, pacing, layout grammar, and reward discipline**.  
Rewrite all player-facing prose from scratch.
